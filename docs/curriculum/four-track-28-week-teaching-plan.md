# KidyCode Four-Track 28-Week Teaching Plan

## Purpose

KidyCode will use one shared learning calendar with four distinct pathways:

1. Code Explorers, ages 10 to 12
2. Code Builders, ages 13 to 15
3. Code Creators, ages 16 to 18
4. Adult Beginners

The pathways will share important ideas such as planning, variables, decisions, testing and project work. They will not share identical explanations or projects. Every group receives language, tools, examples and outcomes suited to its age and goals.

## Course length

- Total length: 28 weeks
- Core learning: weeks 1 to 24
- Capstone project: weeks 25 to 28
- Independent lesson cards each week: 4
- Total core lesson cards: 112
- Optional challenge cards are not required for completion

Each stage lasts two weeks except the final capstone, which lasts four weeks.

## When learners study

### Home and self-paced schedule

- Monday: Discover
- Tuesday: Practise
- Thursday: Debug
- Saturday: Build and explain
- Sunday: Optional catch-up or extension

Ages 10 to 12 lesson cards should take 20 to 30 minutes.

Ages 13 to 15 lesson cards should take 25 to 35 minutes.

Ages 16 to 18 lesson cards should take 30 to 45 minutes.

Adult lesson cards should take 30 to 45 minutes, with optional career exercises lasting longer.

Learners may move the days. The order of the four cards must stay the same.

### School, club or holiday-programme schedule

Combine the same four cards into two weekly sessions:

- Session A: Discover and Practise, 60 to 75 minutes
- Session B: Debug and Build, 60 to 90 minutes

No separate classroom curriculum is needed. The content engine stays the same.

## How every week is taught

### Card 1: Discover

The learner meets one problem, predicts what might happen and reads one short explanation.

Required elements:

- Familiar story or practical situation
- One learning goal
- One new idea
- One visual or worked example
- One prediction before pressing Run

### Card 2: Practise

The learner follows a guided example and changes part of it.

Required elements:

- Starter project
- Small numbered instructions
- Immediate result
- One personal choice
- Three-question understanding check

### Card 3: Debug

The learner receives a project with one or more mistakes.

Required elements:

- Expected result
- Actual result
- Hint level 1: notice
- Hint level 2: inspect
- Hint level 3: worked start
- One tested repair
- Short explanation of the cause

### Card 4: Build and explain

The learner creates a small result using the week's idea.

Required elements:

- Choice of two to four project themes
- Clear minimum requirements
- Test checklist
- Saved evidence
- One explanation in the learner's own words
- Optional extension for learners who finish early

## Independence rules

Every lesson must allow a learner to answer:

- What am I making?
- What should I do now?
- What should happen?
- What can I try if it does not work?
- How do I know I am finished?

A lesson cannot depend on a teacher explaining the page.

New words must open into simple definitions.

Instructions must use action verbs such as choose, drag, type, test, compare and explain.

A wrong attempt must produce a clue and another attempt.

Hints must never reduce the learner's score.

Progress must save after every completed card.

## Group teaching differences

| Pathway | Main teaching style | Core tools | Project context |
|---|---|---|---|
| Ages 10 to 12 | Stories, visual movement, short reading, block coding and guided web activities | Scratch or MakeCode, KidyCode activities, HTML, CSS and light JavaScript | Games, animals, stories, school life, hobbies and community |
| Ages 13 to 15 | Challenges, typed code, comparisons between block and text code, increasing independence | Scratch bridge, Python, HTML, CSS, JavaScript and Git basics | Games, quizzes, useful tools, youth interests and school problems |
| Ages 16 to 18 | Product briefs, documentation, testing, teamwork and portfolio evidence | HTML, CSS, JavaScript, APIs, Supabase, Git, GitHub and deployment | Community products, portfolio applications and real user problems |
| Adults | Practical outcomes, workplace examples, reusable templates and career evidence | HTML, CSS, JavaScript, APIs, Supabase, Git, GitHub, deployment and responsible AI | Small businesses, work tasks, personal productivity, freelancing and client needs |

## The 28-week curriculum

| Weeks | Stage | Ages 10 to 12 | Ages 13 to 15 | Ages 16 to 18 | Adult beginners |
|---|---|---|---|---|---|
| 1 to 2 | 1. Think in steps | Programmer and machine, input and output, precise instructions, decomposition, patterns and prediction | Computational thinking, Scratch diagnostic, input and output, decomposition and clear instructions | Define a problem, identify users, write pseudocode, set up the editor and use the command line safely | Set a practical goal, understand how websites and applications work, organise files and set up the editor |
| 3 to 4 | 2. Algorithms and sequences | Order instructions, move and turn, compare routes, trace steps and repair wrong order | Algorithms, pseudocode, flowcharts, tracing, comparing solutions and first typed commands | Algorithm quality, edge cases, flowcharts, pseudocode and translating plans into JavaScript | Turn a work task into steps, write pseudocode and plan a simple web page before coding |
| 5 to 6 | 3. Input and events | Start, click, key press, movement, position, messages and collision events | Move from Scratch events to browser or MakeCode events, keyboard input and event-driven thinking | HTML structure, CSS foundations, DOM selection, browser events and accessible controls | Build a useful HTML page, add forms and understand clicks, typing and submissions as events |
| 7 to 8 | 4. Repetition and functions | Repeating patterns, counted loops, forever loops, nested loops and runaway-loop debugging | Python loops, range, while, reusable functions and repetition debugging | JavaScript loops, functions, parameters, return values and avoiding repeated code | CSS layouts and reusable JavaScript functions for common page actions |
| 9 to 10 | 5. Variables and data | Named memory boxes, scores, lives, text values, updates and reset controls | Python variables, strings, numbers, lists, dictionaries and state | JavaScript variables, arrays, objects, application state and data transformation | JavaScript variables, calculations, strings, arrays and saving simple page state |
| 11 to 12 | 6. Decisions and validation | True or false questions, if, else, comparisons, touching rules and combined conditions | Python conditions, Boolean logic, user input and validation | Forms, validation, business rules, branching logic and useful error messages | Forms, conditions, calculators, validation and preventing incomplete submissions |
| 13 to 14 | 7. Debugging and testing | Expected versus actual, trace, isolate, repair, retest and the Owl Check | Read errors, use print debugging, test cases, boundary values and repair broken Python programs | Browser developer tools, console debugging, unit-level checks, test cases and accessibility checks | Read browser errors, inspect forms, use the console, test common user mistakes and document fixes |
| 15 to 16 | 8. Interactive experience | Create a branching story with characters, choices, messages and endings | Build a Python quiz or text adventure with functions, score and multiple endings | Build an interactive browser application with DOM events, state and reusable components | Build a practical tracker, planner or calculator that responds to user input |
| 17 to 18 | 9. Complete product | Create a game with rules, score, lives, levels, instructions and play testing | Build a Python or browser game, organise code into functions and test with another learner | Learn product design, user stories, wireframes, accessibility and iterative improvement | Store local data, improve usability and turn a small tool into a repeatable product |
| 19 to 20 | 10. Web and interface foundations | Build a responsive HTML and CSS page about an interest or community idea | Build a responsive multi-section website with semantic HTML and CSS | Fetch information from an API, handle loading and error states and present data clearly | Connect a practical page to an API and show useful information with clear error handling |
| 21 to 22 | 11. Real application data | Use beginner JavaScript to change text, respond to buttons and update a page | Use JavaScript and the DOM to turn a static page into an interactive application | Model data, use Supabase, perform create, read, update and delete operations and understand authentication | Use Supabase to save records, display them, edit them and protect private information |
| 23 to 24 | 12. Safe and responsible building | Online privacy, kind communities, checking information, AI limits and safe project sharing | Git basics, GitHub age requirements, privacy, secure input, AI checking and attribution | Git branches, pull requests, deployment, environment variables, security basics and responsible AI workflows | Git and GitHub, deployment, client privacy, basic security, responsible AI and portfolio presentation |
| 25 to 28 | 13. Capstone and showcase | Plan, build, test and privately present an original game, story, website or useful tool | Build and document a Python or web project for a real user | Build, deploy and document a portfolio-quality application with a real user and database or API | Build and deploy a useful product for a business, client, workplace or personal need |

## What happens inside each two-week stage

### Week 1

- Card 1: Meet and understand the idea
- Card 2: Follow a guided example
- Card 3: Repair one focused mistake
- Card 4: Build a small version

### Week 2

- Card 5: Apply the idea in a different situation
- Card 6: Combine it with a previous skill
- Card 7: Complete an independent challenge
- Card 8: Finish the stage project and explain it

## Capstone timetable

### Week 25: Find and define

- Choose a safe problem.
- Identify the intended user.
- Ask simple research questions.
- Write the goal and minimum features.
- Draw the first interface or project plan.

### Week 26: Build the first version

- Create the smallest working version.
- Test one feature at a time.
- Record bugs rather than hiding them.
- Save a working checkpoint.

### Week 27: Test and improve

- Test with at least two people when possible.
- Record expected and actual behaviour.
- Choose feedback that supports the goal.
- Repair important problems.
- Improve usability and accessibility.

### Week 28: Explain and present

- Finish the project.
- Document what it does.
- Explain one important decision.
- Show one bug and its repair.
- State a known limitation.
- Present privately or publish when appropriate and safe.

## Mastery and progression

A stage is complete only when the learner:

1. Completes all required lesson cards.
2. Scores at least 80 percent on the stage check after unlimited retries.
3. Finishes the stage project.
4. Records at least one test.
5. Explains one decision in their own words.

If the learner is not yet secure, the platform opens a Repair Route containing:

- One shorter explanation
- One new example
- One targeted practice activity
- One second project attempt

The platform must not simply repeat the same failed question.

## Assessment model

| Evidence | Weight |
|---|---:|
| Working project or product | 30 percent |
| Problem breakdown and plan | 15 percent |
| Correct use of the stage concept | 20 percent |
| Testing and debugging evidence | 15 percent |
| Learner explanation | 10 percent |
| Creativity, usability and responsible choices | 10 percent |

For ages 10 to 12, explanations may be short typed sentences or recorded audio.

For ages 13 to 15, explanations should include the purpose of at least one code section.

For ages 16 to 18 and adults, explanations should include decisions, limitations and next improvements.

## Skills at completion

### Ages 10 to 12

Learners can plan instructions, use events, loops, variables and conditions, debug simple projects, create a Scratch project, build a basic webpage and explain their choices.

### Ages 13 to 15

Learners can write beginner Python and JavaScript, build responsive pages, use functions and collections, test and debug code, use Git basics and present a small portfolio.

### Ages 16 to 18

Learners can build and deploy a responsive application, use APIs and a database, work with Git and GitHub, validate input, test software, document limitations and present a portfolio project.

### Adults

Learners can plan and build a practical web product, save and retrieve data, use APIs, Git and deployment, handle basic security and privacy, use AI critically and show evidence suitable for work or clients.

## Content-production order

Content should be written stage by stage across all four tracks so the difficulty differences remain visible.

For each stage:

1. Write the ages 10 to 12 version.
2. Rewrite the concept for ages 13 to 15 using more typed code.
3. Rewrite it for ages 16 to 18 using product and portfolio evidence.
4. Rewrite it for adults using a workplace or practical problem.
5. Review all four versions for accidental duplication or childish language.
6. Build the lesson cards in the platform.
7. Test the child pathway with a learner before opening the next stage.
